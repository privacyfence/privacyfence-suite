PrivacyFence suite setup steps

One thing to do before /implement builds the suite, four checks after it, before the pull request merges, and the first release once it has merged. Your ticks are saved in this browser.

Before implementation

1. Release PrivacyFence 7.0.0b1 and check the four images are public

about 20 min
mb2-upstream-releases

Peek 0.18.0, grist-provisioner 0.2.0 and grist-core 1.7.22-pf.2 are already released. Only PrivacyFence is left.

Done when the tag v7.0.0b1 exists with admin@privacyfence.localhost in single_user_auth.py, and all four docker pulls work anonymously.

After implementation

Use the feature branch named in the pull request. Each check ends with a line to paste into the PR.

2. Run the localhost stack on your own computer

about 15 min
ma1-localhost

Report ma1-localhost: pass, or fail at step N: <what you saw>.

3. Deploy caddy-google on a server

about 45 min
ma2-caddy-google

Report ma2-caddy-google: pass, or fail at step N: <what you saw>.

4. Deploy caddy-idp with your own identity provider

about 45 min; skip if you have none
ma3-caddy-idp

Report ma3-caddy-idp: pass, skipped (no IdP), or fail at step N: <what you saw>.

5. Put nginx-google behind the nginx already on your server

about 30 min
ma4-nginx-google

There is no nginx container: the stack uses the nginx that already runs on the host. You need Linux with rootful Docker and nginx 1.25.1 or later.

Report ma4-nginx-google: pass, or fail at step N: <what you saw>. At step 4, also report the address you saw if it was not your own.

6. Cut the first release and install from it with one command

about 20 min; after the pull request has merged
ma5-release

Report ma5-release: pass, or fail at step N: <what you saw>.
